# МойДом — Цифровой сервис управления МКД в мессенджере MAX

## 1. Назначение решения
«МойДом» — цифровое решение для жителей многоквартирных домов, ТСЖ и управляющих организаций в рамках трека «Умный город». Сервис функционирует как мини-приложение внутри мессенджера MAX и решает задачи прозрачного расчёта начислений ЖКУ, мониторинга домовых коммуникаций, просмотра камер видеонаблюдения подъездов, подачи диспетчерских заявок с фотофиксацией, защищённого общения в домовом чате и проведения юридически легитимных голосований собственников.

## 2. Основной пользовательский сценарий
1. Вход жителя в мини-приложение в мессенджере MAX с предустановленными демонстрационными данными (лицевой счёт квартиры 8, дом 8: г. Белгород, пр-кт Славы, д. 8, кв. 8).
2. Просмотр единого платёжного документа (ЕПД), расчёт услуг по счётчикам и нормативам, моментальная тестовая оплата через СБП с получением номера чека.
3. Контроль статуса инженерных систем дома и онлайн-просмотр видеокамер подъездов с 1 по 5.
4. Создание заявки в аварийно-диспетчерскую службу через центральную кнопку-плюс с прикреплением фотографии.
5. Коммуникация в общедомовом чате с официальными объявлениями ТСЖ и невозможностью удаления чужих сообщений.
6. Участие в опросах дома: невозможность изменить голос без предварительной отмены текущего голоса, фиксация итогов завершённых голосований (13 на 7).
7. Сброс состояния приложения в исходное нажатием верхней левой кнопки обновления.

## 3. Состав и архитектура решения
- `frontend/` — клиентское SPA на React 19 + Vite с мобильной адаптивной вёрсткой под экран смартфона и плавными анимациями смены экранов.
- `backend/` — REST API на базе Python 3.11 и FastAPI.
- `docker-compose.yml` — файл единой контейнеризации и оркестрации клиентской и серверной части.
- `DATA-API.yaml` — формализованная спецификация OpenAPI для тестирования методов API жюри.

## 4. Запуск всех локальных компонентов через Docker одной командой
docker compose up --build -d

После запуска доступны:
- Клиентский интерфейс: [http://localhost:3000]
- Документация REST API (Swagger): [http://localhost:8000/docs]

## 5. Необходимые параметры и переменные окружения
- `VITE_API_ORIGIN` — базовый URL бэкенда (для локального запуска: `http://localhost:8000`, для облака: HTTPS-адрес сервиса).
- `MAX_BOT_TOKEN` — токен команды для платформы MAX (`f9LHodD0cOL3QXIcBTnBfV2YEnl08DmZ2c9ZQjHYBp5N4L9_BJLQB6NQRMmm-Auv643i4pOWraAlUDyw7cXd`).
- `MAX_DEMO_CHAT_ID` — идентификатор тестового чата для уведомлений.

## 6. Используемые порты
- `3000` — веб-интерфейс пользователя (Nginx).
- `8000` — REST API бэкенда (Uvicorn / FastAPI).

## 7. Зависимости
- Серверная часть: Python 3.11, `fastapi>=0.110.0,<0.115.0`, `uvicorn>=0.28.0`, `pydantic>=2.7.0`, `httpx>=0.27.0`, `python-multipart>=0.0.9`.
- **Интерфейс:** Node.js 20, React 19, Lucide-React, Tailwind CSS.

## 8. Внешние сервисы и интеграции
- Платформа мессенджера MAX (Bot API / Webview bridge).
- Протоколы видеонаблюдения RTSP / HLS (в рамках MVP эмулируются потоковым индикатором и интерфейсом видеоокна).
- Интеграция с ГИС ЖКХ и Системой быстрых платежей (смоделированы контракты начислений и чеков).

## 9. Описание работы с данными
Хранение всех состояний (квитанция, чат, заявки, опросы) реализовано в оперативной памяти сервера FastAPI. Это исключает зависимость от внешних СУБД и гарантирует стопроцентную воспроизводимость при проверке жюри. Загружаемые фотографии заявок сохраняются локально в папке `backend/uploads/`.

## 10. Порядок работы с тестовыми данными
По умолчанию система инициализируется квартирой `flat_8` (г. Белгород, пр-кт Славы, д. 8, кв. 8). В системе уже заполнены базовые услуги, сообщения от ТСЖ и завершённый опрос по шлагбауму (13 за, 7 против). При нажатии на круглую кнопку сброса в левом верхнем углу интерфейса все добавленные пользователем данные возвращаются к этому состоянию.

## 11. Пошаговый сценарий проверки
1. Открыть веб-интерфейс по адресу [http://localhost:3000].
2. Вкладка «Счета»:** нажать «Услуга», ввести показания или объём, нажать «Добавить», затем «Оплатить (СБП)» — убедиться в появлении чека и списании суммы в 0.
3. Вкладка «Дом»: проскроллить вниз до блока «Видеокамеры», нажать поочередно кнопки «Подъезд 1» – «Подъезд 5» и убедиться в переключении экранов видеопотока.
4. Центральная кнопка-плюс: нажать круглый плюс в нижней панели, заполнить форму заявки, прикрепить файл фото, отправить и увидеть её в списке активных.
5. Вкладка «Чат»: написать сообщение соседям, убедиться, что удалять можно только свои реплики («Вы (кв. 8)»).
6. Вкладка «Опросы» проверить, что верхний завершённый опрос закрыт и отображает 13 на 7 голосов; в нижнем опросе проголосовать и убедиться, что изменить голос нельзя без нажатия кнопки «Отменить голос».
7. Сброс: нажать на верхнюю левую кнопку «Сброс» (кружок со стрелкой) и убедиться в возврате системы к начальному виду.

## 12. Примеры ожидаемого поведения системы
- Запрос `GET /api/bill` возвращает `paid: false` до вызова оплаты и `paid: true` после.
- Повторный вызов `POST /api/polls/{id}/vote` при наличии активного голоса возвращает `HTTP 400` с текстом: *«Сначала отмените текущий голос, чтобы выбрать другой вариант»*.
- Попытка вызова `DELETE /api/chat/{id}` для чужого сообщения возвращает `HTTP 403` с сообщением: «Удалять можно только свои сообщения».

## 13. Известные ограничения
- Физические RTSP-потоки домофонных камер заменены интерактивным эмулятором видеоокна в связи с отсутствием прямого сетевого доступа к оборудованию МКД на этапе хакатона.
- Транзакции СБП проводятся в тестовом режиме без реального списания денежных средств со счетов.
